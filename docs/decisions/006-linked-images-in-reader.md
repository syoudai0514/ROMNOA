# ADR 006: 本文の画像URLを画像として扱い、拡大はアプリ内で完結させる

採用日: 2026-10-28。

報告の11065781.htmlは、見出し用の画像以外にImgurへの画像リンクが4件ある。従来の抽出はimg要素と一部CDNだけを扱ったため、利用者には見出し画像しか見えず、本文のURLを押すとImgurのページへ移動していた。

固定本文領域にある単一画像リンクとプレーンURLを検証し、画像ブロックへ取り込む。Imgurは許可した静止画像ファイル形式だけをi.imgur.comの直接画像URLへ正規化する。大文字小文字の異なるIDやファイル拡張子を推測しない。拡張子なしのImgurページURLは、同じIDのファイルが本文で確認できる場合だけ対応付ける。広告、任意の画像ホスト、アルバム、リダイレクト先を代理取得する機能は追加しない。

画像は本文を展開する前からギャラリーへ表示し、最初の1枚を優先読み込みする。本文にある画像リンクは外部リンクからアプリ内の拡大ボタンへ変更。既知の関連記事もアプリ内へ遷移する。元ページや通常の外部リンクは区別して残す。

readerPicturesは既に端末やサーバーへ保存したschemaVersion=3のlinksからも画像を再認識する。型は変わらないため本文スキーマとキャッシュnamespaceを維持し、既知記事・親リンクの認可や端末の保存・既読を失わない。元ページ・保存・既読の操作をまとめ、画像が見えるまでの距離を短くする。

画像の復元・改変は行わない。削除済み/アクセス不可の画像や、未対応の配信元を無条件に表示できる保証はしない。一般公開の権利条件・iPhone実機は引き続き未確認。
