# ADR018: 構造による写真ページ判定とYahoo!コメント表示

2026-11-01 採用。

## 写真リンク

### 問題

ADR016〜017以降の修正は、利用者が「写真が出ない」URLを報告するたびにその配信元専用のアダプタを追加する形だった（ORICON、modelpress、日刊スポーツ、デイリー、vois、ENTAME、Real Sound、crank-in…）。報告されていない配信元は同じ形式でも未対応のまま残り、配信元がマークアップを少し変えると専用アダプタが例外を投げ、その後ろの汎用処理まで止めていた。

### 実地調査（Vercel Sandbox・東京リージョン）

この作業環境からは配信元サイトへ接続できない（Yahooのみ許可）。そこで利用者のVercelプロジェクトに一時Sandbox（hnd1）を作り、`scripts/survey-yahoo-links.ts` で9カテゴリRSSの全450記事を実取得し、本文・段落・関連リンクを分類・解決した。失敗・1枚のみの形式は `scripts/trace-sibling.ts` と `scripts/check-photo-pages.ts` で1件ずつHTML構造を確認した。結果は [調査報告](../research/photo-link-survey-2026-11-01.md)。

### 判断

1. **兄弟写真ページ一覧（新・汎用アダプタ `server/sibling-gallery.ts`）**
   写真1枚ごとのHTMLページ＋他の写真ページへのサムネイル一覧、という形式はCMSに関係なく多い。ホスト名ではなく次の構造で判定する。
   - 現在ページと「最後のパス要素だけ」または「数字を含む1つのクエリ値だけ」が異なる同一オリジンのリンクで、画像を含むもの。追跡用クエリ（utm、ref、place、car、ctid…）は無視する。
   - `media/` `video/` `photo/` などの種別フォルダが1階層違うものも同じギャラリーとみなす（Natalie: 写真 `/gallery/news/1/101`、動画 `/gallery/news/1/media/7`）。
   - 広告・関連記事・ランキング・aside・footer内のリンクは使わない。URLかリスト要素に写真・ギャラリーの手がかりが必要。
   - 現在ページが一覧に含まれること（リンク、またはリンクなしの現在サムネイル）。含まれない一覧（同じ節の別ギャラリー）は採用しない。
   - 大きい写真は、現在のサムネイルと同じファイル（サイズ接尾辞・リサイズクエリを除いて一致）のものだけ。一致しなければ採用しない（おすすめ画像やロゴを表示しない）。
   - 80枚を超える一覧は現在の写真の前後80枚に絞り、「取得済み N枚」と元ページ導線を出す。
2. **ギャラリー起点＋番号付きページの連鎖** CinemaToday型（`/gallery/E1` → `rel=next` → `/gallery/E1/002.jpg.html`）を既存の番号付きページ巡回で辿る。40枚・16秒で打ち切り、未取得分は不完全として表示する（従来は例外で全体が失敗）。
3. **専用アダプタの例外で止めない** 専用アダプタが例外を投げても、兄弟ページ・汎用アダプタを続けて試す。後続も失敗した場合だけ最初のエラーを返す。
4. **同一サイト内リダイレクト** WordPressの `?attachment_id=` などは同じオリジンへの301で写真ページに移る。同一オリジンかつ写真リンクとして妥当な移動先に限り2回まで追う。別オリジン・Yahoo記事のリダイレクトは従来どおり拒否。解析は移動先URLで行い、ギャラリー上は記事が指したURLを現在ページとして保つ。
5. **TBS NEWS DIG** `window.GALLERY.total/page` が廃止され、枚数は `js-gallery-more` の `data-max`、位置は表示中の写真で判断する形式へ追従した。
6. **1枚だけのページ** Real Soundの「画像 1 / 1」など、宣言どおり1枚のページは完全取得として扱う。

キャッシュ名前空間は v25 に更新。

### 対応できないもの

- 配信元がアクセスを拒否する（403: WWD JAPAN、webike、CanCam など）。ブラウザを装うUser-Agentでの回避は行わない。
- リンク切れ（Forbes JAPANの404へのリダイレクト、eiga.comの404）。
- JavaScript実行で写真を読み込むページ、外部オリジンへのリダイレクト（abema.go.link）。
- 記事2ページ目などへのリンクで、実際に写真が1枚だけのもの。

これらは従来どおり「元ページで見る」導線を残す。

## Yahoo!ニュースのコメント（口コミ）

利用者の選択により、ROMNOA独自の投稿欄ではなく、Yahoo!ニュース記事に付いている公開コメントを広告なしで表示する。

- `/api/yahoo-comments?article=&page=&order=`。対象はYahoo記事の正規URLだけ。コメントページのサーバー描画データ（`commentFull`）から、その記事IDのコメントだけを読む。ランキング・おすすめ・広告は読まない。
- おすすめ順（Yahooの既定）/新着順、1ページ10件、最大50ページ。専門家（オーサー）コメントは1ページ目の先頭に表示。
- 非表示・ブロック済み・別記事IDのコメントは除外。プロフィール画像は読み込まない。
- コメント欄が閉じている記事（404）は「受け付けていません」と表示。
- 返信本文・投稿・共感などの評価はYahoo!側で行う（返信件数のみ表示、「Yahoo!で開く」）。
- 2分間だけサーバーメモリにキャッシュ。端末には保存しない。
