# ADR017: 写真リンクの対象特定（分類→CMS系統アダプタ→汎用）

2026-10-30 採用（試行）。ADR016以降、配信元ごとの修正が続いた写真特集の対象特定を見直す。

## 問題

0bf6889〜2a792bdの10コミットは、ほぼすべてが「新しい配信元で失敗→その配信元専用の分岐を追加」だった。原因は2つある。

1. **入口で絞っていない。** 本文中のリンクはすべて写真特集候補になり、先頭が自動で「リンク先の写真」として開かれていた。Xの投稿・通販・関連記事・トップページを開くと、汎用パーサーがog:imageや無関係な画像を拾うか失敗する。
2. **出口がホスト名単位。** 文春の写真APIは同じCMS（ARENA）の他社でも同じ構造なのに `bunshun.jp` に固定されていた。IID系（inside-games等）、ザテレビジョン型、crank-in型も同様に、1社ずつ対応した形になっている。

## 判断

3段の流れに分ける。

1. **リンク分類（取得前、URLとリンク文字だけ）** `src/lib/photo-link-classifier.ts`
   - `gallery`：既知の写真ページ形式（MANTAN、modelpress、ARENA `/articles/photo/N`、IID `/article/img/…`、`/gallery/news/N/`、`/news/detail/N/N/`）
   - `photo`：リンク文字（【写真】【画像】全N枚など）やパス（/photo/、/gallery/、?p=）に写真の手がかりがある
   - `article` / `social` / `ignore`：写真特集にしない。SNS（X・Instagram・TikTok・YouTube等）、通販、チケット、アプリストア、短縮URL、トップページ、PDF、Yahoo自身
   - 手がかりの強い順に並べ、同点は記事内の順を保つ。関連リンク（relatedLink）は従来どおりMANTANのみ。
2. **CMS系統アダプタ（取得後、DOMの特徴で判定）** ホスト名ではなくマークアップで判定し、合わなければ次へ落とす。今回はARENAを `#photo-main-carousel` で判定するよう一般化した（文春以外は特徴がなければ `null`）。写真APIは同一オリジンに限る。
3. **汎用パーサー** 既存の `parseLinkedPhotos`（主領域・番号付きページ・サムネイル一覧・JSON-LD）。

キャッシュ名前空間は v11 に更新する（分類が変わるため）。

## 実地調査の手順

全記事のリンク形式は `scripts/survey-yahoo-links.ts` で調べる。全カテゴリのRSS記事を開き、本文・段落・関連リンクを全件抽出して分類し、写真特集になったものは実際に解決を試みる。結果は `links.json`（全リンク）と `summary.md`（ホスト＋パス形状ごとの件数・分類・解決率・エラー）に出す。`--save-html` を付けると解決できなかったページを保存するので、最小化してfixtureにする。

```sh
NODE_USE_ENV_PROXY=1 npx tsx scripts/survey-yahoo-links.ts survey-out --save-html
```

新しい形式への対応は、(1) `summary.md` で件数の多い未解決の形状を選ぶ、(2) 同じCMSの他社がないか確認する、(3) CMS系統アダプタか分類規則として追加する、の順で進める。1社専用の分岐は最後の手段にする。

## X・Instagram

検討した方式:

| 方式 | 評価 |
|---|---|
| ログイン情報（Cookie）をサーバーに保存して投稿を取得 | **今回の方式にはしない。** 公式OAuth/APIの権限とCookieを使う取得は別であり、利用条件・セッション管理を個別に確認する必要がある。Vercelに長期セッションを置くことになり、漏えい時の被害が大きい。2FAやチャレンジで頻繁に失効する。 |
| 端末で事前にログインしておき、公式埋め込みに表示させる | **効果が薄い。** iPhoneのホーム画面PWAはSafariとCookieが分かれており、ITPで第三者Cookieも送られない。埋め込みはログインなしで公開投稿を表示する仕組みなので、ログインの有無はほとんど関係しない。 |
| X: 公式埋め込みが使う公開JSON（syndication）をサーバーで取得 | 候補。ログイン不要で画像・動画URLが取れ、`react-tweet` 等でも広く使われている。ただし非公式で予告なく変わり得るため、失敗時は「Xで開く」に戻す。 |
| X: 公式API v2 | 利用権限・課金・対象投稿の公開範囲に依存。利用量が少なければ従量課金で成り立つかを確認する。 |
| Instagram: 公式埋め込み（タップで読み込み、sandbox付きiframe） | 候補。広告はなく、公開投稿の写真を表示できる。外部スクリプトを読むため、ADR007の「SDK/iframeなし」を「利用者がタップした場合のみ」に緩める判断が要る。 |
| アプリで開く（universal link） | いつでも使える補助導線。ログイン済みのX/Instagramアプリで開ける。 |

### 採用（2026-10-30 追記）

利用者から「X・Instagramもアプリ内で見たい」との指示を受け、ログイン情報を使わない方式で実装した。

- `/api/social?url=`（Preview限定）。投稿URLを正規化し、固定の取得先だけを使う。Xは公式埋め込みが使う公開JSON（`cdn.syndication.twimg.com/tweet-result`）、Instagramは公式埋め込みページ（`/p/<code>/embed/captioned/`）。
- 写真・動画のURLは `pbs.twimg.com`、`video.twimg.com`、`*.cdninstagram.com` に限る。本文・投稿者名・メディアだけを返し、SDK・iframe・外部スクリプトは読み込まない（ADR007の方針は維持）。
- 取得できない場合（削除・非公開・ログイン要求・仕様変更）は「Xで開く／Instagramで開く」だけを表示する。
- 成功は1時間、失敗は5分キャッシュする（Instagramの署名付きURLが失効するため）。
- **実通信は未検証。** このセッションでは両サービスへの通信が拒否されている。どちらも非公式の取得経路で、予告なく変わる可能性がある。

## Yahoo本文の不要リンク除去（2026-10-30 追記）

アプリの目的（広告や誘導なしで読む）に沿って、本文のリンクをサーバー側で振り分ける。

- 削除（リンク文字ごと）：通販・チケット・アプリストア・短縮URL・Yahoo内部（写真ビューアの重複など）・SNSのプロフィール、「関連記事」「あわせて読みたい」「PR」「広告」などで始まるリンク、「購入」「予約」「クーポン」「プレゼント」「キャンペーン」などの販促リンク
- アプリ内表示：SNS投稿は投稿カード、写真リンクは記事内の写真特集へ移動するボタン（特集を取得できなければ元ページへのリンク）
- 外部リンクとして残す：それ以外の記事・公式サイトのリンク

## 影響

本文中の写真以外のリンクは「リンク先の写真」に出なくなる。写真の手がかりが文字にもURLにもない写真ページは候補から外れるので、調査結果を見て分類規則を補う。分類はURLと文字だけで判定しており、内容は保証しない。
