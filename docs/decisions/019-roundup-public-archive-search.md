# ADR 019: まとめの公開アーカイブを検索する

日付: 2026-11-09。状態: 採用。ADR 009/011 の「配信元検索だけで全期間」の扱いを更新。

まとめの「美脚」が18件で終わっていた。配信元キーワード検索は3ページで終わるが、それは公開記事アーカイブ全体の検索完了を意味しない。日付欄を未指定にするだけでは未索引記事は見つからない。

## 取得・照合

キーワード検索の最初の最大5ページで速い結果を出した後、ハムスター速報・アルファルファモザイクの `/archives/YYYY-MM.html` を新しい月から2005年1月まで取得する。月ごとの実在する同一ホストの次ページリンクを最後までたどる。最初のページに `?p=1` は付けない（リダイレクトされる配信元がある）。指定日付があればその期間の月だけを調べ、記事の日付でも絞る。

ページの年月と記事の日付を照合し、サイドバーの新着混入を防ぐ。404/410だけを欠落月として扱い、通信障害・構造変更は空の成功に変換しない。失敗元のページ位置を維持して再開できる。記事IDで重複を除く。タイトルは共通のNFKC・単語AND照合、本文は従来の広告・おすすめ除外済みテキストだけを使う。本文を取得できない候補は未確認のまま数える。

## 保存と進捗

既存の非公開Vercel Blobに、検索語に依存しないページ単位メタデータを保存する。現在の月は10分、過去月は30日の鮮度。任意URLやクライアント提供記事を取り込むAPIにはしない。本文・画像そのものをこの索引に保存しない。

`GET /api/search?index=1` は1呼出し最大4巡・約24秒の予算で索引を作り、各巡の継続位置を保存する。既存の15分ごとの Record news に追加する。手動workflow_dispatchでは最大90分の初回バックフィルを実行する。すべての過去ページが即時検索できるようになった、とは主張しない。初回の取得は時間がかかり、公開ページがない期間は復元できない。

検索中は見つかった結果を逐次追加する。20一致や5ページを理由にアーカイブ検索を止めない。年月・確認済みページ数と途中/完了を表示する。サイト検索の末尾だけでは完了にしない。100グループごとのページ切替でDOMを抑え、件数の数字は折り返さない。端末の保存・履歴・既読は変更しない。

各バッチで照合した記事だけを、従来と同じ検索collectionのサーバー許可リストへ登録してリーダーに渡す。カーソルは記事閲覧許可ではない。

## 検証

単体: 独立した過去記事、次ページ優先、日付/カーソル検証、永続索引の再利用、部分取得失敗、本文未確認、正規の初頁URL、リーダー許可。
ブラウザ: 配信元検索が空でも過去記事を追加、保存/閲覧のcollection維持、100件のページ分け、途中失敗と再開、新しい検索との競合、モバイル横幅。
実ページ: 2025年1月の両サイト22ページを完走。美脚の一致1件（ハムスター速報10842282）を取得。これは配信元検索でも見つかる記事のため、ヒット増加の証拠とは扱わない。検索範囲の修正と全履歴の初回作成完了を区別して報告する。

将来は月単位の集約索引や全文検索DBにより、初回以降の大量ページ照合を短縮する余地がある。今回の変更でYahooニュース検索の提供元側上限を解消したとは扱わない。
