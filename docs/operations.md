# 運用・障害対応

## 起動と検証

Node.js 24 / npm。`npm ci` → `npm run dev`。本番相当ビルドは `npm run build`。通常のVite previewは静的ファイルの確認用でありAPIの運用サーバーではない。

`npm test` はXML/SSRF/XSS/重複/キャッシュ/パーソナライズを検証。`npx playwright install --with-deps chromium webkit` 後に `npm run test:e2e`。`npm run check:feeds` は外部RSSへ各1回アクセスするためCIで毎回実行しない。

## Vercelへの配置

GitHubのROMNOAをVercelでImportしViteを選ぶ。Node.js 24、build `npm run build`、output `dist`。`vercel.json`にhnd1と一覧15秒/本文25秒の上限、CSPを設定済み。DBやアプリAPIキーは不要。個人利用中はPreview Deployment Protectionを維持する。一般公開前に配信元表示条件・実機確認を完了する。

一覧APIは `/api/articles`（クエリ不可）。本文APIは `/api/reader?article=<正規化記事URL>` で、既知のフィード記事・固定数値記事パス、または `&from=<元記事ID>` による確認済み関連記事だけを取得する。親キャッシュの有効期限/リンク完全一致を必須とし、任意URLプロキシは作らない。UI/機密設定をCDNに混在させない。検索・NG・保存はサーバーへ送らない。Vercel Runtime Cacheはサーバーの自動設定を使用。キャッシュが使えない場合はログが出るので本番で確認する。

本文リーダーは認証付きPreview専用。Vercel Authenticationを外さない。本文APIはVERCEL_ENVがpreview以外なら403になる。一般公開・Productionへ拡大する際は、本文利用条件・許諾と認証を先に確認する。APIからのデプロイはtarget=`staging`でPreviewを明示する（初回にtargetを省くとProductionになる場合がある）。

本文は10秒/2MBで取得し、iframeやscriptを実行しない。正常本文を24時間、取得失敗を1分キャッシュ。取得拒否や本文要素変更はエラーにし、迂回・別URL探索・元サイトへの自動遷移は行わない。`reader_fetch_failed`・`reader_cache_read_failed`・`reader_cache_write_failed`を監視する。端末の本文はIndexedDBの最大100件/24時間キャッシュで、従来の保存メタデータとは独立する。

## キャッシュと負荷

- 配信元ごとの成功/失敗を10分間再取得しない。最終正常データは24時間以内に限って利用。
- Vercel Runtime Cacheは永続DBではなく、eviction/cold miss/同時インスタンスによる重複取得は起こり得る。配信元増加や利用量増加時は取得回数を監視し、必要なら単一の収集ジョブと永続ストアへ移行する。
- CDN: max-age=600 / stale-while-revalidate=86400。全件失敗時503/no-store。
- ブラウザ: 検証済み記事データを24時間保持。設定/保存とは独立。サーバーが全件失敗しても保存一覧は開ける。
- 更新ボタンはキャッシュを強制破棄しない。取得間隔を画面に明記。

## 監視

Vercel DashboardでFunction errors、実行時間、Invocation数、転送量、Runtime Cache利用量、ビルド結果を確認。無料枠を超えない保証はない。UIの配信元状態とAPI JSONのstatus/fetchedAtを確認する。ログはsourceIdと固定エラー分類のみで、記事本文やユーザーの検索・NGワードを記録しない。

## 障害対応

| 症状 | 確認・対処 |
|---|---|
| 1サイトのみ失敗 | sources.statusを確認。10分後に再試行。配信元のHTTP状態とRSS形式を確認し、制限回避はしない。他サイトを継続表示 |
| すべて取得失敗 | API503/ログ/配信元状態を確認。ブラウザキャッシュと保存記事を利用。配信元のURLをユーザー入力で差し替えない |
| cache_read/write_failed | Vercel Runtime Cacheの状態・クォータ・環境を確認。空キャッシュでもAPIは動くがアクセス増を監視 |
| XML形式変更 | research台帳と取得仕様を再確認し、パーサーの回帰テストを追加して修正 |
| 保存できない | 容量・プライベートモード・サイトデータ制限を確認。設定画面の削除機能は履歴/既読だけを対象とする。保存記事は残す |
| 更新後に古い画面 | 固定URLを再読み込み、PWAを終了して再度開く。Service Workerは自動更新。保存データ削除を通常の解決手順にしない |
| 権利者の停止・削除要請 | 対象をsources/sourceInfoから削除し、Zod許可IDも更新してデプロイ。Runtime Cacheの当該URLキーとVercel CDNをpurge。端末の過去メタデータはスキーマ検証で読み込み拒否されるが、他の保存記事まで失わない移行を追加する。無断で連絡は送らない |

## 画像優先版の運用

画像は同意ボタンを廃止し、記事表示時に選別した画像だけを許可CDNから遅延読込する。記事画像と別記事サムネイルを混同しない。本文画像は最大80枚、関連記事12件。広告/不明画像を表示するフォールバックはない。画像バイナリのオフライン保存は行わない。

画像がない/保留になる場合は本文ルート・配信フォルダ・リンク先・lazy属性・広告要素を確認し、分類の回帰テストを追加する。CSPへ任意ホストを追加して解決しない。関連記事が開けない場合は親キャッシュが有効か、relatedに対象IDがあるかを確認。新着RSS外の親キャッシュが失効した場合は許可済みの経路から開き直す必要がある。

新しい分類のリリースではRuntime Cacheのv3 namespaceとschemaVersion=3を使用し、旧版本文キャッシュは読込拒否。お気に入り・既読は維持する。画像の見出しとの意味的一致を保証する機能ではない。一般公開の権利条件は未確認のままであり、Preview認証を維持する。

## Pickupとリンクの障害確認

一覧なのに画像が大量に並ぶ場合はpageKindがroundupか、Pickup指定が保持されているかを確認する。実報告の11124247.htmlは複数記事の紹介ページで、最初の直接本編リンクは11089177.html。本文のX画像は10件、見出し画像1件（確認時点）。source CDNだけを許可すると本編画像が欠落する。pbs.twimg.com/media/のURL検証とCSPを確認する。

リンクが文字だけに見える場合はlinks配列とReaderTextの描画を確認。「元ページを開く」は折りたたまず常時表示する。関連記事の本編見出しを「続きを読む」で上書きしない。外部サイトでは広告が表示される可能性がある。元ページの公開本文を読めない場合、アクセス制限を迂回しない。

PWAはautoUpdate/skipWaitingを使用。起動時に登録の更新を確認し、アプリ更新後に再読込されることがある。旧版が残る利用者には新デプロイの固有URLで切り分ける。サイトデータの削除を最初の対処にせず、お気に入り・既読の保存を維持する。

## 画像がリンクのまま・外部へ飛ぶ場合

本文にimgタグではなく画像へのa要素や文字列URLだけがある可能性がある。報告例11065781.htmlはImgurの画像4件と見出し画像1件。readerPicturesが検証済みlinksを画像へ対応付けているか、CSPのimg-srcにi.imgur.comがあるかを確認する。ImgurのHTMLページへiframeを置いたり、任意URLをサーバーで代理取得して解決しない。

画像IDの大文字小文字を維持する。拡張子なしリンクは同一IDの既知ファイルだけへ対応させ、類似ID/別拡張子の総当たりはしない。削除済み・アクセス不可の画像は表示できない場合があり、画像取得失敗は画面に表示する。

本文キャッシュはschemaVersion=3を維持する。新しい画像の抽出だけを理由に端末の保存・既読・サーバーの既知記事を消さない。既存linksの再認識で更新する。利用者には今後更新を反映する固定URL https://romnoa-syoudai1984.vercel.app/ を案内する。デプロイ固有URLは過去版を指し続けるため、日常用URLにはしない。

## MP4・GIF・SNSメディア

本文の対応メディアは自動表示するが通常MP4の再生は利用者操作で行う。本文の「動画Nを再生」はアプリ内のプレーヤーへ移動する。配信元404/削除/公開制限/期限切れ署名はアプリ側で復元できない。読込エラー表示から再読み込みし、元の投稿・記事で公開状況を確認する。見えない動画を任意プロキシやURL総当たりで取得しない。既存linksからも再生対象を導くためキャッシュ削除は不要。

video.twimg.com、i.imgur.com、livedoor固有フォルダ、Instagram CDNの既知MP4のみ対応。HLS、YouTube、全MP4ホストへの対応は未実装。GIFは対応画像ホストの画像として表示。iOSは音声付き動画の自動再生を期待せず、controls/playsInlineのタップ再生を確認する。動画と画像バイナリはオフライン非対応。

X・Instagramは直接メディアURLが記事に含まれる場合だけアプリ内表示。投稿リンクだけの場合は説明と元投稿への明示リンクを出す。Instagram CDNの署名期限切れや公開範囲変更で読めなくなる場合がある。SDK/埋込フレーム・アプリ用SNS APIキーは不要。実機チェックに、MP4再生/一時停止/本文リンクから再生/GIF/アニメーション/取得失敗からの復帰を追加する。

## 人気順・日付別探索

ホームの並び順で「人気順（サイト別）」、掲載日のカレンダーで「表示」。今日/昨日、前の日/次の日、日付を解除を提供。日付は日本時間。人気との併用は現在のランキング記事の掲載日を絞るもので、過去順位ではない。

API: /api/discovery?mode=popular または mode=date&date=YYYY-MM-DD（人気もdate併用可）。任意URL/不正日/未来日/重複パラメータは400、POSTは405。実在日指定の下限は2005-01-01。削除・非公開・サイト開設前・配信元の欠落を復元する機能はない。

Runtime Cache namespaceはromnoa-discovery-v1。人気/今日10分、過去日24時間、失敗1分の取得抑制と最終正常値24時間保持。端末は別キーromnoa:discovery:v1で最近8条件/24時間。古い順位は前回値と表示し、条件が違う一覧を代替にしない。保存/既読/本文v3は削除不要。

監視: discovery_fetch_failed、discovery_cache_read_failed、discovery_cache_write_failed、discovery_failed。一方のソースの障害でも残りを表示。全件失敗は503。一覧が空でも成功していれば対象日/人気との組合せに記事がない可能性があり、新着で埋めない。limitedSourcesがあればページ送り/最大100件などの一部取得を説明する。

構造変更時は元の固定ページ・JSONの字段、JSON文字列リテラル、明示順位、記事見出し/日時を確認し合成fixtureで回帰検証する。JSをevalしたり、任意サイト取得で補わない。本文が開けなければ新鮮なサーバー一覧を開き直し、collectionと対象IDの一致/期限を確認。公開設定を広げない。

実機項目に人気順位/出典、日付選択/日本時間、前後の日、取得障害、保存からの記事表示を追加する。日付の範囲指定、過去順位履歴、iPhone実機確認は未完了。

## 全期間キーワード検索・UI

ホームで語を入力し「検索」。日付は解除し、配信元が検索対象としている全期間を探す。「さらに過去の記事」「前の検索結果」で移動し、そのページ内で新着/ブックマーク数順を切り替える。直近RSSの一覧は入力中の絞り込みとして残す。検索指標の取得不可を0件にせず理由と新着表示を示す。検索先の上限/削除/未索引記事は復元できない。

新API /api/search?q=<語>&page=1..1000[&sources=hamusoku,alfalfa]。80文字/既知配信元/正整数のみ、任意URLパラメータは不可。Runtime Cache romnoa-search-v1（10分/最終正常24時間/失敗1分）、実指標はromnoa-bookmark-counts-v1（10分/失敗1分）。search_fetch_failed/search_cache_* /metrics_*を監視。API呼出しログ・配信元には検索語が渡るため、匿名検索サービスとは扱わない。

端末には検索語を自動履歴保存せず、本文参照用のid/collection/日時だけをromnoa:search-contexts:v1に最大1000件・24時間保持。マイ検索の登録語はromnoa:my-search:v1で最大20件。登録は明示操作で、通常の閲覧履歴・お気に入りは既存の保存方式。

日付選択は年/月カレンダーと週/月/年前のショートカット。404の古い日付一覧はunavailableSourcesとして説明し、全期間キーワード検索を案内する。404を障害再試行や無許可スクレイピングで補わない。

## PIN付きヒントの保守

指定の空白ジェスチャー後、POST /api/hidden-searchでPINを照合。平文PINをログ・コード・運用資料へ記録しない。変更時はサーバーのscrypt照合ダイジェストだけ更新し、正常/異常/失敗抑制/再起動を確認。既存Preview認証を維持する。プロセス内の失敗抑制は分散認証の代替ではない。

ヒントはserver/hidden-catalog.tsの確認済み語だけ。保守時は `NODE_USE_ENV_PROXY=1 npm run check:hints`（プロキシ環境の場合）で実サイトの複数ヒットを確認。CIには入れず、配信元へ不要な反復アクセスをしない。確認に失敗/2件未満なら掲載対象を見直す。件数・確認日を更新する際は実測値だけを使い、総件数/常時ヒット保証と表現しない。0/1件の候補は掲載しない。

隠しメニューの解除は端末へ永続化しない。通常の履歴/保存は共通であることを画面に示す。ソース閲覧者からコード自体を隠す仕組みではない。PINの平文やブラウザ認証情報をテスト成果物へ含めない。
