# ROMNOA 正本設計

## 構成

React 19 / TypeScript / Vite / Tailwind CSS 4。Vercel Node.js 24 Function `GET /api/articles` とUIを分離する。認証・DB・AI・広告SDKは導入しない。

`server/sources.ts` → 安全なRSS取得 → XMLパーサー → 正規化・重複排除 → JSON API → React → localStorage。

画面: ホーム（検索・並び順・カテゴリ・記事）、カテゴリ（件数と選択）、保存（お気に入り/履歴）、設定（配信元・NGワード・文字・テーマ・PWA案内）。記事詳細はモーダルで出典/日時/元記事導線/保存/既読/前後移動を提供する。全文や外部HTMLは描画しない。

## データ

Article: id（正規化URL）、url、sourceId、title、publishedAt（不明はnull）、category。本文/画像/広告/外部埋込はAPIにも保持しない。FeedResult: 記事、ソースごとのstatus/取得日時、generatedAt。

端末保存v1: お気に入りのメタデータ（最大200件）、既読/履歴（500件）、テーマ、文字サイズ、NGワード、非表示配信元、表示位置。Zodによる復元時検証、破損時の復旧と書込失敗時の通知。記事キャッシュは24時間、設定とは別キー。容量不足でもアプリ操作は継続する。

## 安全性と取得負荷

- URLは固定のHTTPSフィードのみ。リクエストのクエリを拒否し任意URL取得を許可しない。リダイレクトは拒否。ホスト・パスは設定だけが指定。
- 6秒タイムアウト、展開後1MB上限をstreamで強制。DOCTYPE/ENTITY拒否、XML構文検証、entity展開無効。フィードからのリンクも配信元ホストに限定。
- sanitize-htmlでタイトルをプレーンテキスト化しReact文字列で表示。dangerouslySetInnerHTMLなし。
- 正常/失敗とも次回アクセスを10分抑制。Vercel Runtime Cacheに最終正常データを24時間保持。ローカル開発だけメモリを利用。同一プロセスの同時取得はまとめる。Runtime Cacheは分散ロックではないため複数インスタンスの同時cold missは発生し得る。
- CDNは成功/部分成功を10分キャッシュ、最大1日stale。全件失敗は503/no-storeにして最後のブラウザキャッシュを利用。
- 検索・配信元選択はブラウザ処理。同じAPIパスを共有してキャッシュ分断を防ぐ。
- 外部画像・iframe・script読込なし。CSPで同一オリジンに限定。元記事はユーザーの明示操作で別タブに開く。

## 重複と順序

追跡パラメータ/fragment除去・HTTPS正規化で同一記事を識別。類似タイトルは文字bigramのDice係数0.88以上かつ24時間以内の場合にのみ表示時に折り畳み、展開できる。断定的な同一記事認定や人気スコアには使わない。検索結果は取得済み記事内だけ。カテゴリはRSS分類とタイトルのルールベース推定で正確性を保証しない。

## PWA

Service Workerでアプリシェルをprecache。APIはSWでキャッシュせず、検証後の端末キャッシュを使用。更新は通知して明示的に切り替える。iOSはSafari共有メニューから「ホーム画面に追加」。外部本文のスクロール位置は別オリジンなので管理できず、ロムノア内の一覧/詳細位置のみ復元する。
